# Браузер по умолчанию в Windows

Установщик регистрирует Nocturne в HKCU через RegisteredApplications, StartMenuInternet/Capabilities и ProgID NocturneURL. HTTP/HTTPS указывают на команду `"Nocturne.exe" -- "%1"`. Разделитель `--` отделяет ссылку от параметров Chromium и профиля. HTML-файлы не объявляются поддерживаемыми, пока их локальное открытие не реализовано.

Новая кнопка находится в Настройках → Основные и поиск. На Windows 11 она открывает карточку Nocturne через `ms-settings:defaultapps?registeredAppUser=Nocturne`; на Windows 10 — общий системный выбор. Там пользователь подтверждает приложение. Регистрация доступности не изменяет UserChoice и не назначает браузер принудительно. Переносимая сборка может зарегистрировать собственный exe по нажатию кнопки; запуск исходников не регистрируется.

Статус HTTP/HTTPS проверяется через `app.getApplicationInfoForProtocol` и путь фактического обработчика, а не через `isDefaultProtocolClient`: последний в Electron проверяет старый ключ Classes/protocol и не отражает современный выбор Windows.

Параметры запуска принимают только HTTP/HTTPS, с ограничением длины и количества, без встроенного логина/пароля. Внешние ссылки всегда выбирают новую вкладку, даже при настройке фонового открытия. Работают холодный запуск, очередь до готовности UI и second-instance. Приватный профиль не регистрируется отдельной командой.

Проверки: модульные тесты валидатора и регистрации; реальная регистрация во временном собственном пространстве HKCU с проверкой неизменности HTTP/HTTPS UserChoice и очисткой; Electron cold/warm smoke с сохранением формы и проверкой аргументов после `--`. Фактический пользовательский выбор по умолчанию не менялся.

Документация: https://learn.microsoft.com/en-us/windows/apps/develop/launch/launch-default-apps-settings и https://learn.microsoft.com/en-us/windows/win32/shell/default-programs.
